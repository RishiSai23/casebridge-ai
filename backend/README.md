# CaseBridge AI — Backend

Python/FastAPI backend for **CaseBridge AI** (SIH 2026, AICTE Problem Statement 26264).  
This service exposes a REST API that the frontend team consumes.  All endpoints live under `/api/v1/`.

---

### Design decisions

| Decision | Rationale |
|---|---|
| FastAPI | Async-native, automatic OpenAPI docs, first-class Pydantic integration |
| SQLAlchemy 2.x typed ORM | Full type inference; async session via asyncpg |
| asyncpg driver | High-performance native async PostgreSQL driver |
| Alembic | Schema migrations decoupled from application startup |
| VARCHAR enums (not PostgreSQL ENUM type) | No `ALTER TYPE` required to add values |
| Lazy engine initialisation | App starts and serves health checks without a database |
| TimestampMixin (server_default) | Timestamps set by PostgreSQL — immune to Python clock drift |
| Append-only CaseEvent | Tamper-evident timeline; events are never modified |
| Partial unique index on aicte_institution_id | Multiple NULLs allowed; no duplicate non-null IDs |
| Canonical pair ordering in CaseRelationship | Prevents (A→B) and (B→A) duplicate rows |
| Human-only relationship confirmation | AI score is evidence; status changes require explicit reviewer action |

## Domain entities and relationships

### Entity summary

| Entity | Table | Purpose |
|---|---|---|
| **User** | `users` | Platform staff (bureau officers, analysts, admins) |
| **Institution** | `institutions` | Educational institutions referenced in complaints |
| **Bureau** | `bureaus` | AICTE bureaus / cells that handle complaints |
| **ComplaintCase** | `complaint_cases` | A single complaint filing |
| **CaseAssignment** | `case_assignments` | Which bureau owns a case (full transfer history) |
| **CaseEvent** | `case_events` | Append-only timeline of case activity |
| **CaseRelationship** | `case_relationships` | Proposed / confirmed links between cases |
| **CoordinationAction** | `coordination_actions` | Cross-bureau coordination work items |
| **AuditLog** | `audit_logs` | Immutable record of significant administrative changes |

### Foreign-key relationships

```
Institution ──< ComplaintCase >──── Institution (one institution, many cases)
ComplaintCase ──< CaseAssignment >── Bureau
ComplaintCase ──< CaseEvent
ComplaintCase ──< CaseRelationship (as source or target)
ComplaintCase ──< CoordinationAction (primary case)
ComplaintCase ──< CoordinationAction (related_case, optional)
User ──< CaseEvent (actor_user_id, nullable)
User ──< CaseAssignment (assigned_by, nullable)
User ──< CaseRelationship (reviewed_by, nullable)
User ──< CoordinationAction (assigned_to, nullable)
User ──< AuditLog (actor_user_id, nullable)
```

### Key constraints

| Constraint | Table | Description |
|---|---|---|
| Partial unique index | `institutions` | `aicte_institution_id` unique among non-null values |
| Partial unique index | `case_assignments` | Only one `active` + `unassigned_at IS NULL` row per case |
| CHECK | `case_relationships` | `source_case_id != target_case_id` (no self-links) |
| CHECK | `case_relationships` | `source_case_id < target_case_id` (canonical ordering) |
| UNIQUE | `case_relationships` | `(source_case_id, target_case_id, relationship_type)` |
| CHECK | `case_relationships` | `confidence_score` in [0.000, 1.000] when present |

### Deletion behaviour

| FK column | `ondelete` | Rationale |
|---|---|---|
| `complaint_cases.institution_id` | `RESTRICT` | Cannot delete an institution with active cases |
| `case_assignments.case_id` | `RESTRICT` | Assignments must be cleaned up before deleting a case |
| `case_assignments.bureau_id` | `RESTRICT` | Cannot delete a bureau with assignment history |
| `case_events.case_id` | `RESTRICT` | Event history must not be lost |
| `case_relationships.source/target_case_id` | `RESTRICT` | Relationship evidence must not be silently lost |
| `audit_logs.actor_user_id` | `SET NULL` | Audit records survive user deactivation |
| `case_events.actor_user_id` | `SET NULL` | Events survive user deactivation |
| `coordination_actions.related_case_id` | `SET NULL` | Action survives if the related case is removed |

## CaseRelationship status semantics

| Status | Meaning | Who sets it |
|---|---|---|
| `potential` | System-generated or manually proposed relationship awaiting review | AI engine or bureau officer |
| `confirmed` | A reviewer has validated the relationship | Human reviewer only |
| `dismissed` | A reviewer determined the link is not valid or useful | Human reviewer only |

> **Critical rule:** A `confidence_score` alone NEVER changes a relationship's status.  
> No autonomous merging or confirmation of cases is permitted.

## Configuration

Copy `.env.example` to `.env` and edit before running:

```powershell
Copy-Item .env.example .env
```

| Variable | Default | Description |
|---|---|---|
| `APP_ENV` | `development` | `development` \| `staging` \| `production` |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | Comma-separated allowed frontend origins |
| `DATABASE_URL` | `postgresql+asyncpg://casebridge_dev:change_me_local_dev@localhost:5432/casebridge_dev` | `postgresql+asyncpg://USER:PASSWORD@HOST:PORT/DBNAME` |
| `AI_SIMILARITY_THRESHOLD` | `0.75` | Min cosine similarity to flag complaint overlap |
| `AI_MAX_OVERLAP_CANDIDATES` | `10` | Max candidates returned per complaint |
| `LOG_LEVEL` | `INFO` | Python log level |

> When `APP_ENV=production`, the `/docs`, `/redoc`, and `/openapi.json` routes are disabled.

## Local setup

```powershell
# From the backend/ directory:

# 1. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 2. Install all dependencies (including SQLAlchemy, asyncpg, Alembic)
pip install -r requirements.txt

# 3. Configure environment
Copy-Item .env.example .env
# Edit .env if needed (defaults match the repository root docker-compose PostgreSQL service)

# Optional: start local PostgreSQL first (from repository root)
# docker compose up -d postgres

# 4. Start the development server
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

The API will be available at `http://localhost:8000`.  
Interactive docs: `http://localhost:8000/docs`

## Database migrations (Alembic)

> **All commands must be run from the `backend/` directory with the virtual environment active.**

### Prerequisite

Set `DATABASE_URL` in `.env` (or export it in the shell) before running Alembic commands that load migration env config.

### Initial migration

```powershell
# Initial schema migration is committed in:
# alembic/versions/20261020_2f4e9a1b8c72_initial_domain_schema.py

# Show available revisions from local migration files (no DB connection required)
alembic history --verbose
```

### Review and apply

```powershell
# Preview SQL for the latest revision (requires DATABASE_URL, but no live DB connection)
alembic upgrade head --sql

# Apply migrations (requires running PostgreSQL instance)
alembic upgrade head

# Verify current migration state (requires running PostgreSQL instance)
alembic current

# Create a new revision for future schema changes
# Usually requires a reachable PostgreSQL database for autogenerate comparison.
alembic revision --autogenerate -m "describe_change"
```

### Rollback

```powershell
# Roll back the most recent migration
alembic downgrade -1

# Roll back to a specific revision
alembic downgrade <revision_id>
```

## API reference — Health endpoints

### `GET /api/v1/health`

Liveness probe. Returns `200 OK` whenever the process is running.

**Response — 200 OK**

```json
{
  "status": "ok",
  "app": "CaseBridge AI",
  "version": "0.1.0",
  "environment": "development",
  "timestamp": "2026-10-20T05:16:30.123456Z"
}
```

### `GET /api/v1/health/ready`

Readiness probe. Returns `503` when `DATABASE_URL` is not configured (expected until Task 3).

**Response — 503 (DATABASE_URL empty)**

```json
{
  "status": "degraded",
  "checks": { "database": "DATABASE_URL not configured" },
  "timestamp": "2026-10-20T05:16:30.123456Z"
}
```

**Response — 200 (DATABASE_URL set)**

```json
{
  "status": "ready",
  "checks": { "database": "ok" },
  "timestamp": "2026-10-20T05:16:30.123456Z"
}
```
