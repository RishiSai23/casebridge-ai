# API v1 Directory (`backend/app/api/v1/`)

## A. Purpose
The `backend/app/api/v1/` directory contains all Version 1 REST API route definitions, request/response handlers, and route aggregation for CaseBridge AI.

## B. Directory tree
```
backend/app/api/v1/
├── __init__.py            # Makes v1 a Python package
├── health.py              # Health check endpoints (/health and /health/ready)
├── router.py              # Aggregates and mounts all v1 sub-routers
└── v1.md                  # Navigation documentation for the v1 API directory
```

## C. File inventory
| File | Responsibility |
|---|---|
| `__init__.py` | Marks `v1` as a Python package. |
| `health.py` | Implements liveness probe (`GET /api/v1/health`) and readiness probe (`GET /api/v1/health/ready`). |
| `router.py` | Consolidates all v1 endpoint routers into a single `api_v1_router` included in `main.py`. |
| `v1.md` | Documents the v1 routing architecture, endpoint catalog, and endpoint development rules. |

## D. Subdirectory inventory
There are currently no subdirectories in `backend/app/api/v1/`.

## E. Relationships and dependencies
- Mounted into the root FastAPI application inside [app/main.py](../../main.py) with prefix `/api/v1`.
- Uses configuration settings from [app/core/config.py](../../core/config.py).
- Uses response schemas defined in [app/schemas/health.py](../../schemas/health.py).
- Future modules (institutions, complaints, bureaus, relationships, coordination) will be registered into `router.py`.

## F. Development and verification
Verified by automated tests in [backend/tests/test_health.py](../../../tests/test_health.py):
```powershell
pytest tests/test_health.py -v
```
Manual verification using local server:
```powershell
uvicorn app.main:app --reload --port 8000
# In another terminal:
curl http://localhost:8000/api/v1/health
```

## G. Maintenance notes
- All v1 endpoints should be mounted through `router.py`. Do not mount sub-routers directly in `main.py`.
- Keep route handler functions concise; delegate business logic, AI operations, and validation pipelines to `app/services/`.
- Ensure appropriate HTTP status codes, Pydantic response models, and OpenAPI tags on all routes.
